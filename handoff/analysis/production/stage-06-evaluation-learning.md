본 파일은 제작팀 수행 역할의 분석 보존본이다. 기존 분석 시점의 ‘미실행’ 표현은 당시 상태를 보존한다. 최신 실행 상태는 아래 관리 기록과 연결된 테스트 결과로 구분한다.

# 6단계 평가·지식 축적 — 검증 전 분석 기록

작성일: 2026-10-23
상태: 미검증 후보안. 확정 지침이 아님.

## 기록 목적과 반영 범위

지금까지 정리한 내용을 향후 테스트·실증 검증을 위한 가설과 판단 근거로 보존한다. 사용자의 지시에 따라 테스트 결과를 확인하기 전에는 구조 개선, 시스템화, 공통 지침 및 실행 스킬 반영을 확정하지 않는다. 이 기록에서는 이미지 생성, 실험 실행, 효과 검증을 수행하지 않았다.

## 제로베이스에서 본 목적

평가·지식 축적의 목적은 기록량을 늘리는 것이 아니라 다음 제작에서 더 정확한 결정을 내릴 수 있도록 재사용 가능한 근거를 남기는 것이다. 예쁜 결과물의 보관과 개선 효과의 입증을 구분한다.

## 평가 대상은 분리한다

| 평가 대상 | 확인하려는 내용 | 해석상 주의점 |
|---|---|---|
| 제품 정확성 | 원본 대비 형태·비례·구성·옵션의 보존 | 미관 점수가 높아도 제품 오류를 상쇄할 수 없음 |
| 연출과 컷 목적 | 요구한 구매 질문에 필요한 시각적 증거를 제공하는지 | 보이지 않는 부분은 정확하다고 단정할 수 없음 |
| 제작 효율 | 최초 통과, 재시도, 수정 시간, 전체 비용 | 선택된 성공작뿐 아니라 실패 시도도 포함 |
| 고객 이해 | 제품 형태·크기·사용 상황을 올바르게 이해하는지 | 내부 평가자의 취향과 구분 |
| 판매 성과 | 실제 구매 행동과 연결되는지 | 가격·혜택·유입 등 다른 요인과 분리해 검증 필요 |

단일 종합 점수로 치명적 제품 오류를 가리지 않는다. 제작 품질의 개선, 고객 이해의 개선, 판매 성과의 개선은 각각 별도의 근거를 요구한다.

## 축적할 지식의 최소 단위

“어떤 문제에서, 어떤 조건으로, 무엇을 바꾸었고, 무엇이 개선되었으며, 무엇은 아직 모르는가”를 기록한다.

권장 기록 항목은 다음과 같으며 고정 양식으로 확정한 것은 아니다.

- 제품·옵션·원본 참조 및 작업 버전
- 컷의 목적, 공간·카메라·조명 조건
- 관찰한 오류와 근거 위치
- 변경 변수와 비교 대상
- 전체 시도 수, 통과 수, 보류·판정 불가 수
- 수정 시간·비용과 다른 품질의 악화 여부
- 평가자 판단과 불일치 사유
- 적용 가능한 범위, 반례, 미확인 사항

전체 실험 기록과 실제 제작 시 참고할 짧은 요약은 연결해 보존한다. 과거의 모든 조건을 매번 실행 지시에 누적하는 방식은 후보로 채택하지 않는다.

## 오르보 식탁에 적용한 가설 예시

실제 제품의 확정 치수·소재·공식 옵션 대응은 이 기록에서 확인하지 않았다. 아래는 실험 설계 예시이며 성공 사례가 아니다.

| 항목 | 검증 전 후보 내용 |
|---|---|
| 문제 | 생성 결과에서 다리와 프레임 연결 형태가 원본과 달라질 가능성 |
| 가설 | 전체 제품 사진에 해당 연결부 원본을 추가하면 구조 보존이 개선될 수 있음 |
| 비교 | 전체 사진만 제공한 조건과 연결부 사진을 추가한 조건 |
| 공통 조건 | 동일한 제품·컷 요청·도구 버전·재시도 및 시간 예산 |
| 관찰 | 연결부 정확성, 전체 비례, 새로운 결함, 전체 작업 시간 |
| 해석 제한 | 특정 각도의 개선만으로 다른 각도·옵션·가구 유형에 일반화하지 않음 |

원본에서 구조를 확인할 수 없는 부분은 추측으로 정답을 만들지 않는다. 가려진 부분은 판정 불가로 남기며, 컷의 목적상 보여야 할 부분이 가려졌다면 목적 미충족으로 별도 평가한다.

## 검증 설계 후보

1. 현재 방식의 기준 결과와 판정 기준을 먼저 기록한다.
2. 비교할 핵심 변경을 명시하고 다른 조건을 가능한 한 맞춘다.
3. 평가 항목·시도 횟수·예산·중단 조건을 결과 확인 전에 정한다. 구체적 수치는 아직 미정이다.
4. 성공작만 선별하지 않고 모든 시도와 수정 이력을 남긴다.
5. 가능한 경우 결과의 조건명을 가린 상태에서 원본과 대조하고, 평가자 간 불일치를 기록한다.
6. 같은 조건의 반복 뒤에 보지 않은 컷·옵션·제품으로 적용 범위를 확인한다.
7. 통과율은 분자와 분모를 함께 보고하고, 불충분한 결과는 효과 없음으로 단정하지 않는다.
8. 개선 효과와 함께 비용·부작용·예외를 확인한 후 반영 여부를 별도로 판단한다.

이 절차 역시 실증 전 제안이다. 현재 테스트 횟수, 통과 기준, 허용 오차, 채택 임계값은 확정하지 않았다.

## 지식 상태와 유지 후보

상태 후보: 미검증 → 시험 결과 있음 → 반복 확인 → 적용 범위 확인. 별도로 반례 있음·반박됨·재검증 필요를 표시할 수 있다. 시험을 한 번 수행한 사실과 효과가 검증된 사실을 구분한다.

제품이나 도구 버전이 바뀌면 기존 지식의 유효성을 재확인한다. 중복 기록은 통합하고 효과가 없거나 반박된 규칙은 실행 요약에서 제외하되 판단 이력은 보존한다. 이 상태 체계 자체도 아직 확정하지 않는다.

## 지식 축적 체계 자체의 검증

- 같은 오류가 다시 발생하는 빈도가 줄어드는가.
- 제작자가 필요한 근거를 빠르게 찾고 올바르게 적용하는가.
- 수정 시간과 총비용이 줄어드는가.
- 기록·검색 부담이 얻는 이익보다 과도하지 않은가.
- 다른 컷이나 제품에 적용했을 때 오히려 정확도가 떨어지지 않는가.

## 향후 검토할 산출물 후보

전체 시도 기록, 적용 범위가 명시된 개선 요약, 성공·실패 대조 사례를 우선 후보로 둔다. 자동 지침 갱신과 시스템 구조 변경은 검증 결과 및 별도 반영 판단 전까지 보류한다.

## 현재 상태

분석 기록만 완료. 이미지 생성 없음. 테스트·실증 검증 미실행. 구조 개선·시스템화·공통 지침 변경 없음. 모든 제안의 확정 및 반영 보류.


## 관리 상태 및 변경 이력
- 담당 파일 소유: 제작팀. 상대 팀 파일은 참조만 하며 수정하지 않는다.
- 현재 상태: **실증 검증 전·미확정**. 원본 대조나 단일 시험 착수는 실증 완료가 아니다.
- 이번 파일은 분석 보존 문서이며 공통 지침·스킬·공식 시스템에 반영하지 않는다.
- 갱신 시 이 파일을 읽고 현재 내용과 변경 이력을 함께 수정한다. 검증 결과는 테스트 ID·결과 파일·커밋으로 연결한다. 기존 반례와 실패 이력은 삭제하지 않는다.
- 자동 감시나 다른 채팅 자동 실행은 설정하지 않았다. 후속 작업에서 변경을 확인했을 때 갱신한다.

| 날짜 | 변경 내용 | 이유 | 검증 근거 | 남은 한계 |
|---|---|---|---|---|
| 2026-10-23 | 제작팀 소유의 단계별 분석 기록 최초 등록 | 사용자 요청에 따른 보존 및 변경 추적 | 이전 대화 분석·기존 기록·요청서 대조. 효과 실증 근거는 없음 | 반복 재현·독립 검수·고객 검증 미완료 |

향후 행 형식: 날짜 / 변경 전후 요점 / 변경 이유 / 테스트 ID·파일·커밋 및 직접 관찰 / 반례·적용 범위·미확인.
